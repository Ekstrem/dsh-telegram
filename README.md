# dsh-telegram

Telegram-канал для DeepSeek Harness: настоящие таблицы и списки, передача изображений в обе стороны, вопросы с кнопками и управление моделью прямо из чата.

Этот репозиторий — **русская сборка** пакета [`dsh-telegram`](https://github.com/Gum97/dsh-telegram) версии 0.2.0 (автор — Gum97, лицензия MIT). Оригинальный README сохранён в [`README.upstream.md`](./README.upstream.md).

## Что изменено относительно 0.2.0

**Локализация.** Весь служебный интерфейс бота переведён на русский: приветствие `/start`, `/help`, меню команд, подписи инструментов («⚙️ выполняю команду…»), кнопки вопросов, сообщения об ошибках, описания в карточке настроек. В `lib/i18n.js` добавлен полноценный словарь `ru`, `DEFAULT_LANGUAGE` переключён на `ru`, `LANGUAGES` расширен до `vi | en | ru`. Словари `vi` и `en` сохранены.

**Выбор сессии.** Добавлена команда `/sessions`: сначала выбирается рабочая папка (workspace), затем сессия внутри неё — как в сайдбаре DSH.

**Последний ответ.** Команда `/last` показывает последнее сообщение агента в текущей сессии; после подключения к сессии последний ответ приходит автоматически.

**Исправлены ошибки** (обе ломали подключение к существующим сессиям):

- `sessionPersistence.list()` возвращает обёртки `{ header, revision, sizeBytes }`, а код читал `entry.id`. Из-за этого `sessionExists()` всегда отвечал `false`, и `agents.resume()` не вызывался никогда — плагин всегда создавал новую сессию.
- Ошибки обращения к хранилищу проглатывались и выглядели как «сессий не найдено». Теперь причина видна в чате.
- `sessionPersistence` резолвится через `ctx.inject`, а не голым `ctx.get()`.

## Требования

DSH `0.2.0-rc.2` (проверено на этой версии) и Node.js ≥ 20.

## Установка

```sh
dsh plugin --profile desktop add github:Ekstrem/dsh-telegram
```

Затем добавить бандл в `~/.dsh/profiles/desktop/package.json`:

```json
{
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-telegram"]
    }
  }
}
```

Токен бота хранится не в конфиге плагина, а в credential-провайдере. Проще всего — в `$DSH_HOME/.env`, который читается при старте:

```sh
TELEGRAM_BOT_TOKEN="123456:ABC-DEF..."
```

Токен подхватывается **только при запуске DSH** — после добавления переменной нужен перезапуск.

## Конфигурация

Профильный патч `~/.dsh/profiles/desktop/cordis.patch.yml`:

```yaml
- id: telegram
  disabled: false
  config:
    allowedUsers:
      - "211320390"        # Telegram user id, строки
    language: ru           # vi | en | ru
    # workspaceRoot: C:\path\to\workspace   # рабочий каталог сессий Telegram
```

`allowedUsers` — именно user id, не chat id (у групп они отрицательные). Пустой список означает, что бот не закреплён: первый отправивший `/start` становится владельцем.

Поля `streaming`, `showToolActivity`, `rich`, `preset`, `bindingFile` описаны в `lib/index.js`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Приветствие |
| `/help` | Список команд |
| `/new` | Новая сессия для этого чата |
| `/sessions` | Подключить чат к существующей сессии: папка → сессия |
| `/sessions <id или название>` | Быстрый поиск по всем папкам |
| `/last` | Последний ответ агента в текущей сессии |
| `/model` | Показать и сменить модель |
| `/preset` | Сменить профиль агента для новых сессий |
| `/mode` | Права записи файлов (sandbox) |
| `/status` | Статус текущей сессии |
| `/stop` | Остановить текущий ход |
| `/compact` | Сжать историю диалога |
| `/clear` | Очистить историю и начать заново |

## Как работает привязка чата к сессии

Соответствие «чат → сессия» хранится в `~/.dsh/dsh-telegram/bindings.json`. `/sessions` записывает туда новый `sessionId` и вызывает `agents.resume()`, поэтому выбранная сессия продолжается со всей историей. Файл кешируется при старте: правки вручную требуют перезапуска.

Список для `/sessions` собирается из `sessionPersistence.list()` плюс `workspaceRegistry`:

- архивные сессии (`workspaceRegistry.archivedSessionIds`) скрыты;
- сессии субагентов (`origin: 'subagent'`) скрыты;
- названия берутся из проекционного кэша (`sessionProjectionCache`), того же, что рисует сайдбар;
- порядок — по времени последнего сообщения (`sessionListMetadata.lastPromptAt`), свежие сверху; при отсутствии данных — по `createdAt`.

## Известные ограничения

- **Карточка настроек в браузере не локализована.** `lib/client.js` — предсобранный бандл, в нём остались ярлыки `vi`/`en`. На сообщения бота это не влияет.
- **Не открывайте одну и ту же сессию в Telegram и в вебе одновременно** — получится два агента на одной истории.
- Если проекционный кэш не отвечает, кнопки сессий показывают короткий id вместо названия.
- Плагин не умеет перезапускать себя: смена токена, `workspaceRoot` и включение/выключение применяются после перезапуска DSH.

## Структура

```
lib/            исполняемый код (ESM, без сборки)
cordis.patch.yml  патч бандла: монтирует запись `telegram`
package.json    метаданные пакета
```

Файлы в `lib/` — источник истины для этой сборки; отдельного шага сборки нет, `lib/client.js` поставляется как есть.
