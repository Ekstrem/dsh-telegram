# dsh-telegram-ex

Telegram-канал для DeepSeek Harness: настоящие таблицы и списки, передача изображений в обе стороны, вопросы с кнопками и управление моделью прямо из чата.

**Русская сборка** пакета [`dsh-telegram`](https://github.com/Gum97/dsh-telegram) версии 0.2.0 (автор — Gum97, лицензия MIT). Оригинальный README сохранён в [`README.upstream.md`](./README.upstream.md).

## Что изменено относительно 0.2.0

**Локализация.** Весь интерфейс бота — приветствие `/start`, `/help`, меню команд, подписи инструментов («⚙️ выполняю команду…»), кнопки вопросов, ошибки — переведён на русский. В `lib/i18n.js` добавлен словарь `ru` и выставлен дефолтом; `LANGUAGES` = `ru | en`. Вьетнамский словарь удалён. Карточка настроек (`lib/client.js`) локализована тем же образом: свой словарь `ru`, язык по умолчанию — русский.

**Выбор сессии.** Команда `/sessions`: сначала рабочая папка (workspace), затем сессия внутри неё — как в сайдбаре DSH.

**Последний ответ.** Команда `/last` показывает последнее сообщение агента в текущей сессии; после подключения к сессии последний ответ приходит автоматически.

**Исправлены ошибки** (обе ломали подключение к существующим сессиям):

- `sessionPersistence.list()` возвращает обёртки `{ header, revision, sizeBytes }`, а код читал `entry.id`. Из-за этого `sessionExists()` всегда отвечал `false`, и `agents.resume()` не вызывался никогда — плагин всегда создавал новую сессию.
- Ошибки обращения к хранилищу проглатывались и выглядели как «сессий не найдено». Теперь причина видна в чате.
- `sessionPersistence` резолвится через `ctx.inject`, а не голым `ctx.get()`.

## Требования

DSH `0.2.0-rc.2` (проверено на этой версии) и Node.js ≥ 20.

## Установка

Из npm:

```sh
dsh plugin --profile desktop add dsh-telegram-ex
```

Напрямую из этого репозитория:

```sh
dsh plugin --profile desktop add github:Ekstrem/dsh-telegram
```

Затем добавить бандл в `~/.dsh/profiles/desktop/package.json`:

```json
{
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-telegram-ex"]
    }
  }
}
```

Если раньше стоял оригинальный `dsh-telegram`, его нужно удалить из `dependencies` и из списка `bundles`, иначе два плагина одновременно попытаются держать long-polling одного токена.

Токен бота хранится не в конфиге плагина, а в credential-провайдере. Проще всего — в `$DSH_HOME/.env`, который читается при старте:

```sh
TELEGRAM_BOT_TOKEN="123456:ABC-DEF..."
```

Переменная подхватывается **только при запуске DSH** — после добавления нужен перезапуск.

## Конфигурация

Профильный патч `~/.dsh/profiles/desktop/cordis.patch.yml`:

```yaml
- id: telegram
  disabled: false
  config:
    allowedUsers:
      - "211320390"        # Telegram user id, строки
    language: ru           # ru | en
    # workspaceRoot: C:\path\to\workspace   # рабочий каталог сессий Telegram
```

`allowedUsers` — именно user id, не chat id (у групп они отрицательные). Пустой список означает, что бот не закреплён: первый отправивший `/start` становится владельцем.

Остальные поля (`streaming`, `showToolActivity`, `rich`, `preset`, `bindingFile`) описаны в `lib/index.js`.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Приветствие |
| `/help` | Список команд |
| `/new` | Новая сессия для этого чата |
| `/sessions` | Подключить чат к существующей сессии: папка → сессия |
| `/sessions <id или название>` | Быстрый поиск по всем папкам |
| `/last` | Последний ответ агента в текущей сессии |
| `/topics` | Разложить сессии папки по топикам форум-группы |
| `/history [N]` | Последние N ответов в этой сессии (по умолчанию 10) |
| `/model` | Показать и сменить модель |
| `/preset` | Сменить профиль агента для новых сессий |
| `/mode` | Права записи файлов (sandbox) |
| `/status` | Статус текущей сессии |
| `/stop` | Остановить текущий ход |
| `/compact` | Сжать историю диалога |
| `/clear` | Очистить историю и начать заново |

### Закрытые сессии: `wake`

По умолчанию канал **не поднимает** сессию с диска: агент, собранный из контекста
плагина, получает только глобальные инструменты, и рабочий реестр треда схлопывается
(проверено: 27 → 1). Сообщение в закрытую сессию сохраняется и уходит само, когда вы
откроете её в DSH; в чат приходит подсказка `💤 Сессия «…» не загружена`.

| Параметр | Смысл |
|---|---|
| `wake` | `live-only` (по умолчанию) или `resume` — поднимать с диска, рискуя инструментами |
| `pendingTtlHours` | сколько часов держать сообщение, ждущее открытия (по умолчанию 6) |

Ответы всегда уходят в тот чат/топик, из которого пришло сообщение, даже если сессия
привязана к нескольким чатам.

### Зеркало ответов: `mirrorAnswers`

По умолчанию канал отдаёт в чат только те ходы, которые сам начал. С `mirrorAnswers: true`
в топик попадают **все** ответы привязанной сессии — включая ходы, запущенные веб-интерфейсом
или другим плагином (мост LoopMaker). Стриминг для таких сессий отключён: приходит готовый
ответ, без промежуточных превью.

`/history 15` в топике отдаёт последние 15 ответов этой сессии из лога — полезно, когда
нужно поднять контекст с телефона.

## Как работает привязка чата к сессии

Соответствие «чат → сессия» хранится в `~/.dsh/dsh-telegram/bindings.json`. `/sessions` записывает туда новый `sessionId` и вызывает `agents.resume()`, поэтому выбранная сессия продолжается со всей историей. Файл кешируется при старте: правки вручную требуют перезапуска.

Список для `/sessions` собирается из `sessionPersistence.list()` плюс `workspaceRegistry`:

- архивные сессии (`workspaceRegistry.archivedSessionIds`) скрыты;
- сессии субагентов (`origin: 'subagent'`) скрыты;
- названия берутся из проекционного кэша (`sessionProjectionCache`), того же, что рисует сайдбар;
- порядок — по времени последнего сообщения (`sessionListMetadata.lastPromptAt`), свежие сверху; при отсутствии данных — по `createdAt`.

## Форум-группы и топики

Ключ привязки включает id топика: `tg:<chatId>:<threadId>`. Поэтому в супергруппе с включёнными темами **каждый топик — отдельная сессия со своей историей**, и переключение сессий сводится к переключению топиков в интерфейсе Telegram.

`/topics` материализует выбранную рабочую папку: для каждой сессии создаётся топик с её названием (`createForumTopic`), привязка пишется сразу, уже разложенные сессии пропускаются. Топики создаются с паузой 1.1 с, чтобы не упереться в лимиты Telegram, и в фоне — группа не блокируется.

Требования: группа должна быть **супергруппой с темами**, а бот — **администратором с правом «Управление темами»**. Без статуса админа бот к тому же не увидит обычные сообщения группы из-за privacy mode.

## Известные ограничения

- **Не открывайте одну и ту же сессию в Telegram и в вебе одновременно** — получится два агента на одной истории.
- Если проекционный кэш не отвечает, кнопки сессий показывают короткий id вместо названия.
- Плагин не умеет перезапускать себя: смена токена, `workspaceRoot` и включение/выключение применяются после перезапуска DSH.

## Структура

```
lib/              исполняемый код (ESM, без сборки)
cordis.patch.yml  патч бандла: монтирует запись `telegram`
package.json      метаданные пакета
```

Файлы в `lib/` — источник истины для этой сборки; отдельного шага сборки нет, `lib/client.js` поставляется как есть.
